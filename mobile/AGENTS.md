# Chatter mobile

The Android (later iOS) client for Chatter. See ROADMAP.md for what is done
and what is next.

## How it is built

- **Shared logic lives in `../packages/core`** (imported as `@chatter/core/*`):
  the API, the store (reducer, socket handler, actions), the message format.
  The web client runs the same files. A fix to how a room loads or a message
  parses is made there, once. Anything platform-specific goes through `host`
  (`packages/core/src/platform.ts`); this app's implementation is
  `src/platform/host.ts`.
- **`src/platform/`** is the phone's side: Web Storage (expo-sqlite), the
  refresh token in the Keystore, the chosen server, toasts, the event bus.
  `install.ts` runs before anything else (see `index.ts`).
- **`src/state/ChatterProvider.tsx`** is the store plus a phone's lifecycle
  (restore from Keystore, socket on foreground/background). It adds no
  actions of its own beyond sign-in/out: new actions go in core.
- **Styling is Uniwind** (Tailwind 4): use the web's classNames (`bg-card`,
  `text-muted-foreground`). Colours come from `src/theme/themes.css`,
  generated from `client/src/index.css` by `npm run port-theme` — never hand
  edit it. Text goes through `T` (`src/ui/primitives.tsx`) for the font; it
  turns the web's `font-medium`/`font-bold` into the right JetBrains Mono
  family. Uniwind's rem is the web's 17.6px (`metro.config.js`), so a class
  is the same size on both.
- **Look like the web, built like a phone.** A screen here is the web
  component it corresponds to (`client/src/components/…`), with its
  classNames copied, adapted only where a phone needs it: a pressed state for
  hover, 44px targets, a sheet for a dropdown. Read the web component before
  writing or changing one here. Controls (buttons, badges, inputs, the
  segmented switch) come from the recipes both apps share in
  `../packages/core/src/ui/recipes.ts`; the web's `components/ui` files and
  `src/ui/controls.tsx` here are both built on them, so change the look there.
  The web's text roles (`ui-heading`, `ui-meta`, `ui-hint`) are in
  `src/ui/roles.ts`.
- **Changing core from here?** The web client builds from the same files:
  run `cd ../client && npm run build` as well as the checks below. CI
  (`.github/workflows/clients.yml`) checks core, web and mobile together.
- **Native code** is local Expo modules in `modules/` (Kotlin):
  `chatter-call` (call foreground service, audio routes, proximity, picture-in-
  picture, self-managed Telecom so a phone call holds the call),
  `chatter-fold` (hinge and posture), `chatter-share` (Android share target).
  `android/` is generated by `npx expo prebuild` — never edit it; configure in
  `app.config.ts` and config plugins.
- **Gestures** use react-native-gesture-handler v3's hook API
  (`usePanGesture`, `GestureDetector`). Rightward swipes belong to the panels,
  leftward ones to messages (swipe to reply) unless they start at the edge.

## The changelog

A change people using the app would notice gets a line in `CHANGELOG.md`
under "Unreleased" (New, Changed or Fixed), written for them: what changed,
in plain words, no code names. It is shared as the release notes and shown in
Settings → What's new, which `npm run changelog` generates from it.

## Building on Windows

Long paths must be enabled, and a CMake ≥ 3.31 installed in the SDK
(`sdkmanager "cmake;3.31.6"`); `plugins/withLongPathCmake.js` points the
build at it. Build the dev variant with `APP_VARIANT=development`.

## Testing against a server

Never point development at a server other people use. `scripts/dev-backend.ps1`
runs a private one (its own MongoDB on :27018); `scripts/seed-dev.mts` fills
it. Test accounts live in `~/.chatter-dev/test-accounts.json`, outside the repo.

## Commands

```bash
npm run typecheck && npm run lint             # before calling anything done (CI runs both)
npm run changelog                             # after editing CHANGELOG.md (CI checks it)
npx expo install <package>                    # never npm install: picks the SDK's version
npm run prebuild                              # regenerate android/ after app.config or modules/ change
cd android && ./gradlew app:assembleDebug     # dev APK (APP_VARIANT=development); install with adb install -r
npx expo start --dev-client                   # Metro for the dev build
```

Releases are APKs installed by hand, not store builds. Push notifications
(FCM) and release signing are **on hold until the project owner says
otherwise** — don't start either.

## Expo moves fast

Check `expo` in `package.json` (SDK 58) and read the matching versioned docs,
`https://docs.expo.dev/versions/v58.0.0/`, before using an Expo or React Native
API from memory. Routes live in `src/app/` (Expo Router); keep everything else
outside it.
